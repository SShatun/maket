# Новый персонаж

Для сцены нужен объект, которого нет в каталоге мира. Его рисуют в манере дизайнера, проверяют, смотрят рядом с эталонами и добавляют в каталог. В следующих роликах он уже есть. Команды общие; у Пикселей и Орков исходник состоит из клеток, у Моэ из гладких фигур.

Каталог: `assets/live/` для Пикселей, `assets/looks/rts/` для Орков, `assets/looks/moe/` для Моэ. Внутри `sprites.json` и папка на каждый образ. Правила рисования указаны в `rules` каталога или `look.json`: у Пикселей это `assets/design/live-pixels.md`, у остальных `rules.md` рядом с каталогом.

Команды запускаются из корня репозитория как `go run ./cmd/maket char …`. Из другой папки добавляют `-root <корень>`. Мир выбирается `-look rts` или `-look moe`; без `-look` это Пиксели. Флаги идут после имени или пути, как в примерах ниже.

## Есть ли уже такой

`go run ./cmd/maket char list -look rts` печатает имя, подпись, синонимы, состояния и происхождение. Подходящий по смыслу образ лучше нового: «прайс» в Пикселях это `tariff`, «шахта» у Орков это `db`. Новый рисуют, только когда ни один не читается как нужный объект.

## Эталоны

Прочитать файл правил целиком. Выбрать двух-трёх персонажей дизайнера, близких по форме, и посмотреть их листы. С них берут пропорции, толщину обводки, тени, лицо, отступы и точку ног. Сравнивают не только покой, но и общие состояния.

```
go run ./cmd/maket char sheet warrior -look rts -ref worker,session -o out/review/rts-references.png
go run ./cmd/maket char sheet service -look moe -ref topic,db -o out/review/moe-references.png
```

У пиксельных миров снять ещё сетку:

```
go run ./cmd/maket char grid parcel idle
go run ./cmd/maket char grid warrior walk -i 1 -look rts
```

Один символ сетки означает клетку `pixel`×`pixel` px готового PNG. У Пикселей это 32×40 клеток по 12 px. У Орков клетка тоже 12 px, но размеры и точки ног у разных образов свои; у всех `top.y = 24`. На карте один логический пиксель занимает 6 px. Дракон в каталоге имеет холст 48×40 клеток.

У Моэ холст 1040×1200 px, `anchor: [520, 1120]`, `top: [520, 300]`. Сетки нет: `grid` объясняет это и предлагает PNG. Эталон смотрят в исходном разрешении; гладкую обводку нельзя переводить на клетки.

## Исходник

### Сетка Пикселей и Орков

`grid.txt`:

```
palette . transparent  k 24,28,40  W 255,255,255  S 214,214,214
pixel 12
anchor 192 456
top 192 96
rest idle
tint true
state idle fps 2 loop
frame 0
................................
(строки сетки, все одной длины)
state catch fps 10 once
frame 0
...
```

- Цвета только из палитры персонажей дизайнера выбранного мира. `grid` печатает палитру эталона, `check` принимает цвета всех эталонов.
- Серые r=g=b перекрашиваются цветом роли; лицо, кожа и эффекты цветные. `tint false` нужен, если цвет материала сам говорит, что это, например картон.
- `anchor` ставят в точку ног, `top` в место для значка. Общие у эталонов координаты сохраняют.
- Обязательны `rest` и общие состояния мира: сейчас везде `catch` и `flinch`, по 3 кадра. Остальные состояния нужны по смыслу: у дракона `idle`, `walk`, `attack`, как у воина.

### Гладкий рисунок Моэ

Рисуют прозрачные PNG `<состояние>_<номер>.png`, начиная с нуля. Используют фигуры, кривые и сглаживание, как у эталонов; сохраняют редактируемый исходник рядом. Цветные кожа и волосы не перекрашиваются, одежда цвета роли нейтрально-серая, белое тёплое 255/252/247. Палитру и толщину линии здесь сравнивают глазами: точное совпадение цветов по краям после сглаживания не требуется.

Рядом нужен `entry.json`, например для трёх обязательных состояний:

```json
{
  "size": [1040, 1200], "anchor": [520, 1120], "top": [520, 300],
  "scale": 2, "rest": "idle", "tint": true, "source": "source.svg",
  "states": {
    "idle": {"frames": 2, "fps": 2, "loop": true},
    "catch": {"frames": 3, "fps": 10, "loop": false},
    "flinch": {"frames": 3, "fps": 12, "loop": false}
  }
}
```

`pixel` у гладкого рисунка отсутствует. `source` это имя одного файла рядом с `entry.json`, например SVG или скрипта рисования. Сборка копирует исходник и PNG, но не запускает скрипт. Пример: `assets/looks/moe/painter/source.py` рисует состояния художницы через CairoSVG. Для повторной отрисовки нужен Python с `cairosvg` и библиотекой Cairo; для обычной сборки и сцены они не нужны.

## Сборка, проверка, лист

```
go run ./cmd/maket char build grid.txt -look rts -o /tmp/draft/dragon
go run ./cmd/maket char check /tmp/draft/dragon -look rts
go run ./cmd/maket char sheet /tmp/draft/dragon -look rts -ref warrior,session,worker -o out/review/dragon.png

go run ./cmd/maket char build /tmp/drawing/entry.json -look moe -o /tmp/draft/painter
go run ./cmd/maket char check /tmp/draft/painter -look moe
go run ./cmd/maket char sheet /tmp/draft/painter -look moe -ref service,topic,db -o out/review/painter.png
```

`check` проверяет размеры PNG, непустые кадры, опоры, `rest`, состояния, число кадров и положительную частоту. У пиксельных миров дополнительно проверяет клетку и палитру. Смена `pixel` на 1 не позволяет обойти правила каталога. У Орков размеры могут различаться, общие координаты опор сохраняются; у Моэ размеры и обе опоры фиксированы.

Лист показывает новый образ рядом с эталонами в общем масштабе и на одной линии ног, в исходном цвете и в двух ролях, включая тёмную. Ниже все кадры нового образа с подписями. На него смотрят глазами: читается ли объект, держит ли лицо на тёмной роли, не суетлив ли, похожа ли рука на соседей. `check` этого не решает. Чужая манера требует перерисовки исходника и повторной сборки. После четырёх неудачных кругов черновик оставляют вне каталога с описанием того, что не получилось.

## Добавление и сцена

До `add` посмотреть `git status -- <каталог>/sprites.json <документ мира>`. Чужие незакоммиченные правки не включают в свой коммит.

```
go run ./cmd/maket char add /tmp/draft/dragon -look rts -name dragon -label 'дракон с крыльями' -alias 'дракон,крылатый зверь,dragon'
```

`add` сам повторяет `check` и без него ничего не добавляет. Имя состоит из строчной латиницы, цифр, `-` и `_`; имя персонажа дизайнера занять нельзя. Ранее добавленный образ с тем же именем заменяется. Запись получает `origin: "generated"`, рядом с кадрами остаются `entry.json` и исходник. Исходники дизайнера имеют `origin: "designer"`.

`-label` и хотя бы один синоним в `-alias` обязательны. `add` обновляет таблицу мира из каталога: Пиксели в `docs/scene.md`, Орки в `docs/styles/rts.md`, Моэ в `docs/styles/moe.md`. У другой стилистики документ `docs/styles/<look>.md` должен уже существовать. Таблица между метками `characters:start` и `characters:end` заменяется целиком; подписи правят в каталоге, а не внутри таблицы. `char list -markdown -look rts` выводит эту же таблицу для сверки.

Затем проверить `char list` заново: по подписи и синонимам этот рисунок найдут в следующем ролике. `generated` означает, что образ добавлен позднее; `designer` отличает исходные рисунки. Синонимы служат поиску, а в `kind` пишут имя из первого столбца.

Сцена берёт имя через `kind`, код мира менять не надо. У Орков верх сцены `"style": "rts"`, у Моэ `"style": "moe"`; поле `look` в этих сценах не задаётся. Новые короткие примеры: `scenes/rts-dragon-crossing.json` и `scenes/moe-painter-sketch.json`.

Для проверки рисунка достаточно кадров без голоса:

```
go run ./cmd/maket stills scenes/rts-dragon-crossing.json -o out/review/rts-frames -silent 0.5 2.6 4.6 6.2
go run ./cmd/maket stills scenes/moe-painter-sketch.json -o out/review/moe-frames -silent 0.5 3.6 6.6
```

Перед коммитом посмотреть листы и кадры. Коммит включает только свои исходники, PNG, запись каталога, таблицу и новую сцену; формат заголовка берут из правил репозитория.

## Предметы, места и значки

| Чего не хватает | Как сохранить и найти снова |
|---|---|
| Предмета или здания: ворот, сундука, мольберта | Во всех трёх мирах это тот же образ `sprites.json`: `build`, `check`, `sheet`, `add`, затем `kind` в сцене. Подпись, синонимы, происхождение и таблица сохраняются так же. |
| Места в Пикселях | Положить PNG в `assets/live/backdrops/` или `assets/looks/<look>/backdrops/`, записать имя и метаданные в `look.json.backdrops`. `styles` покажет его; сцена выбирает `place` по имени. |
| Места в Моэ | PNG или JPEG 1080×1920 в `assets/looks/moe/backdrops/`, запись в `look.json.backdrops` и свет под тем же именем в `backdrops/backgrounds.json`. `styles` покажет подпись, синонимы, происхождение и пол; `place` принимает новое имя. |
| Места в Орках | Карта собирается из `map`, фиксированных деревьев, камней и травы. Новый фон или набор мест пока не подключается одним каталогом; работа записана в `docs/backlog.md`. |
| Нового значка над головой | В Пикселях и Орках список значков пока задан кодом; в Моэ поле `badges` не поддерживается. Новый файл сам не появится в списке. Общая регистрация, описание и проверка значков записаны в `docs/backlog.md`. |

Неподвижный предмет тоже имеет общие `catch` и `flinch` по три кадра; если он не реагирует, кадры повторяют. Для новых ворот в Пикселях и Орках нужны `allow` и `deny`, а точка прохода совпадает с `anchor`. Тогда `admit` принимает их id независимо от имени образа. Новый тип поведения предмету команда рисования не добавляет.

Места хранятся отдельно от персонажей: у них другой размер и нет состояний. Пример записи внутри `look.json.backdrops`:

```json
"workshop": {
  "file": "backdrops/workshop.png", "floor": 1640,
  "label": "светлая мастерская", "aliases": ["ателье", "комната", "workshop"],
  "origin": "generated"
}
```

У Моэ дополнительно внутри `backdrops/backgrounds.json.backgrounds`:

```json
"workshop": {
  "floor_y": 1640, "bright": 1,
  "light": {"amb": [255, 240, 220], "amb_k": 0.15,
            "rim": [255, 230, 190, 255], "rim_dir": [1, -1]}
}
```

Это пример структуры; цвет и направление света выбирают по рисунку. `bright: 1` делает подложку голограмм тёмной на светлом фоне, `0` оставляет прозрачной; допустимы промежуточные значения. `floor: null` означает отсутствие пола. После добавления запустить `go run ./cmd/maket styles` и снять кадр новой сцены с `-silent`: проверка персонажей фон не проверяет. PNG, исходник места и записи сохраняют вместе; исходник можно положить рядом с фоном. Полный единый цикл `char check/add` для мест и значков пока не реализован.

## Режиссёру: чего не хватает истории

Сначала выбрать мир по разделу «Для каких историй» в `docs/styles/<мир>.md`. Выписать состав истории: кто действует, какие предметы и состояния нужны. Сверить его с `char list` выбранного мира по подписям и синонимам, а не только по имени. Для мест отдельно посмотреть `styles`.

```
go run ./cmd/maket char list -look rts
go run ./cmd/maket char list -look moe
go run ./cmd/maket char list
go run ./cmd/maket styles
```

Если образ уже есть, взять его `kind` из первого столбца. Например, дракон уже `dragon`, художница `painter`; повторно рисовать их не надо. Если не хватает только состояния, назвать именно его: подходящий рисунок без нужной позы ещё не закрывает запрос.

Запрос на новый образ должен читаться без истории ролика. В нём нужны имя каталога, что изображено и по каким деталям узнаётся, мир, все нужные состояния с числом кадров, два-три эталона для соседства на листе. Указать подпись и синонимы для будущего поиска, что красится ролью и что сохраняет цвет материала. Так выглядел запрос на художницу до её добавления:

> Имя `painter`, мир `moe`. Художница-чиби с беретом, кистью и палитрой; подпись «художница с кистью и палитрой», синонимы «художник, иллюстратор, рисование, artist». Состояния: idle 2 кадра, paint 3, wait 3, happy 2, catch 3, flinch 3; rest idle. Эталоны рядом: service, topic, db. Одежда и берет цвета роли, волосы, кожа, дерево палитры и краски сохраняют свои цвета. Холст и опоры как у эталонов.

### Сколько заняло рисование

Измерено по часам от начала рисунка после просмотра эталонов до успешного `check` и осмотра листа. Круг это рисунок, сборка, проверка и просмотр. Обе пробы прошли с первого круга; правки раскладки сцен в это число не входят.

| Образ | Кадров | Время | Кругов до принятия |
|---|---|---|---|
| dragon, Орки | 15 | 4 мин 44 с | 1 |
| painter, Моэ | 16 | 2 мин 29 с | 1 |

Интервалы пересекались, поэтому их не складывают. Это две пробы, а не обещание срока: первичное изучение мира, новая сцена и коммит считаются отдельно. Проверка манеры остаётся зрительной; одного `ok` от `check` недостаточно.
