# Новый персонаж

Для сцены нужен объект, которого нет в каталоге стилистики. Его рисуют по сетке в манере дизайнера, проверяют, смотрят рядом с эталонами и добавляют в каталог. В следующих роликах он уже есть.

Каталог стилистики — `assets/live/` или `assets/looks/<look>/`: `sprites.json`, папка на каждого персонажа, правила рисования в файле из ключа `rules` (у Пикселей `assets/design/live-pixels.md`). Команды запускаются из корня репозитория как `go run ./cmd/maket char …`, из другой папки — с `-root <корень>`; все берут ещё `-look L`.

## Есть ли уже такой

`go run ./cmd/maket char list` печатает имя, подпись, синонимы, состояния и кто нарисовал. Подходящий по смыслу персонаж лучше нового: «прайс» — это `tariff`, «склад» — `external` или `db`. Новый рисуют, только когда ни один не читается как этот объект.

## Эталоны

Прочитать файл правил целиком. Снять сетки двух-трёх персонажей дизайнера, близких по форме, в покое и в общих состояниях:

```
go run ./cmd/maket char grid parcel idle
go run ./cmd/maket char grid template catch -i 1
```

Сетка — столько строк и символов в строке, сколько клеток у холста эталонов (у Пикселей 40 строк по 32 символа), один символ — клетка `pixel`×`pixel` px готового кадра (у Пикселей 12), легенда символов в строке `palette`. С эталонов копируют обводку, толщину, тени, глаза и рот, отступы от краёв и точку ног.

## grid.txt

```
palette . transparent  k 24,28,40  W 255,255,255  S 214,214,214
pixel 12
anchor 192 456
top 192 96
rest idle
tint true
state idle fps 2 loop
frame 0
................................
(строки сетки, все одной длины)
state catch fps 10 once
frame 0
...
```

- Цвета — только те, что есть у персонажей дизайнера этого каталога: `char grid` печатает палитру одного эталона, `check` принимает цвета их всех. Серые r=g=b перекрашиваются цветом роли; лицо, кожа и эффекты — цветные. `tint false` — если цвет материала сам говорит, что это (картон).
- `anchor` и `top` — как у эталонов.
- Обязательны состояния, которые есть у всех эталонов (у Пикселей `catch` и `flinch`, по 3 кадра), и `rest`. Остальные — по смыслу объекта.

## Сборка, проверка, лист

```
go run ./cmd/maket char build grid.txt -o /tmp/draft/<имя>
go run ./cmd/maket char check /tmp/draft/<имя>
go run ./cmd/maket char sheet /tmp/draft/<имя> -o /tmp/draft/sheet.png -ref parcel,template,db
```

`check` проверяет размер, клетку, палитру, состояния и опоры. Лист ставит новый персонаж во всех состояниях рядом с эталонами и в двух цветах ролей; на него смотрят глазами: читается ли объект, не суетлив ли, держит ли лицо на тёмной роли, стоят ли ноги как у соседей. Правят `grid.txt` и повторяют шаг, не больше 4 кругов (число — по пробе тарифа, ей хватило трёх).

Не вышло за 4 круга: черновик удалить, в каталог ничего не добавлять, сказать пользователю, какой объект не получился и почему.

## Добавление и коммит

До `add` посмотреть `git status -- <каталог>/sprites.json docs/scene.md`. Есть чужие незакоммиченные правки — персонажа добавить, но не коммитить, и сказать пользователю.

```
go run ./cmd/maket char add /tmp/draft/<имя> -name <имя> -label <подпись> -alias <синонимы через запятую>
```

`add` сам повторяет `check` и без него ничего не добавляет. Имя — строчная латиница, цифры, `-` и `_`; имя персонажа дизайнера занять нельзя, а сгенерированного с тем же именем `add` заменяет. Запись получает `origin: "generated"`, рядом с кадрами ложится `grid.txt`.

Дописать строку персонажа в таблицу `docs/scene.md` (имя, кто, состояния кроме `catch` и `flinch`): агент роликов выбирает персонажа по ней. Затем коммит только своих путей, заголовок как в `git log` репозитория:

```
git add -- <каталог>/<имя> <каталог>/sprites.json docs/scene.md
git commit -m "[<задача>] Character <имя>" -- <каталог>/<имя> <каталог>/sprites.json docs/scene.md
```
